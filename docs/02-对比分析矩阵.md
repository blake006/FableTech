## 1. 总体判断

先把结论放在前面：

| 维度 | 赢家 | 说明 |
|---|---|---|
| 检测通过率 | **CloakBrowser** | 30+ 检测系统实测全过，reCAPTCHA v3 0.9 分 |
| 免费开源程度 | **Camoufox** | MPL-2.0 全源码，唯一完全免费且改内核的 |
| 自动化隐身（CDP 层） | **Patchright** | 修 Runtime.enable 泄漏，Playwright drop-in |
| 指纹真实性 | **BrowserForge**（生成）+ Camoufox/CloakBrowser（注入） | 统计分布 + 内部一致性 |
| 产品化完整度（GUI/档案管理） | **CloakBrowser Manager**（参照） | 但依赖付费引擎；FableTech 要免费替代 |
| 社区规模 | CloakBrowser（32k★）/ camoufox（12.6k★） | 都在日更 |

**没有任何单一开源仓库**同时满足：免费 + 指纹伪装 + 多档案 GUI + 代理管理 + 自动化。这是 FableTech 的组装空间。

## 3. 逐项优缺点详评（针对 FableTech 场景）

### 3.1 Camoufox —— 主引擎首选

**优点**
- 唯一**完全免费 + 源码级指纹注入**的成熟方案，无并发限制、无许可证雷区
- 指纹**内部一致性**由 BrowserForge 保证（UA/屏幕/GPU/时区互不矛盾），这正是商业产品「档案指纹」的精髓
- Firefox 路线：CDP 检测重灾区天然规避；内存占用 ~200MB，一台机器多开 5~10 个档案无压力
- 日更活跃，跟随 Firefox 版本，长期可维护
- Playwright API 兼容，我们的自动化配方代码可直接复用

**缺点**
- 基于 Firefox：极少数站点对 Chromium 有硬性要求（个别 Web 应用、银行类站点）→ 需要 Patchright-Chromium 作为备选引擎
- 官方定位偏「AI Agent 抓取」，headless-first；headed 人工操作可用但需我们自己在产品层做好体验
- 无自带档案管理 GUI —— 这正是 FableTech 要补的

**适配度**：⭐⭐⭐⭐⭐（社媒注册/养号主力引擎）

### 3.2 CloakBrowser —— 可选增强引擎

**优点**
- 检测通过率实测最强，Cloudflare Turnstile / reCAPTCHA v3 / FingerprintJS / BrowserScan 等 30+ 系统全过
- 拟人化交互（贝塞尔鼠标、键盘节奏、滚动物理）一个开关搞定，对「行为风控」型平台（TikTok、X）价值大
- Manager 已跑通「引擎 + 档案 GUI + CDP 端点」的产品形态，架构可参照

**缺点**
- **引擎二进制按并发收费**（免费 1 并发）且**禁止再分发/改装** —— 无法预装进便携包、不能转售给客户；自用需订阅
- 二进制不随 GitHub 源码构建（wrapper + 远程下载），供应链上我们无法审计引擎本体
- 项目新（2026-02），生态与稳定性待时间验证
- Manager 仓库 license 为 NOASSERTION（与官网宣称 MIT 不符），代码不可直接商用

**适配度**：⭐⭐⭐（对付高难度站点的付费外援；不进入便携包默认组件）

### 3.3 Patchright —— Chromium 自动化补丁层

**优点**：Apache-2.0、drop-in、日更、Chromium 自动化隐身事实标准；可配合系统已装 Chrome 零成本起步。

**缺点**：**不伪造指纹**（多档案共用本机真实指纹会被关联）；仅 Chromium；console API 被关闭（调试略有不便）。

**适配度**：⭐⭐⭐⭐（仅作为「必须 Chromium」站点的备选引擎 + CDP 泄漏修补技术参考）

### 3.4 nodriver / undetected-chromedriver / puppeteer-extra / rebrowser-patches

| 项目 | 不采用原因 |
|---|---|
| nodriver | 无指纹伪装能力；AGPL-3.0 传染性 |
| undetected-chromedriver | 2025-07 起实质停更（1142 open issue，issues 关闭） |
| puppeteer-extra(stealth) | 2024-07 停更；JS 注入路线已被现代检测识破 |
| rebrowser-patches | **无许可证**（法律风险）+ 2025-05 停更；功能被 Patchright 覆盖 |

### 3.5 BrowserForge —— 指纹生成核心

**优点**：真实统计分布 + 内部一致性 + 与 Camoufox 同生态；Apache-2.0。
**缺点**：只是库，需产品层做「档案种子持久化」（同一档案每次启动必须产出同一指纹 —— 这点 FableTech 必须在架构上保证）。
**适配度**：⭐⭐⭐⭐⭐（必选组件）

## 4. 场景适配度专项分析（社媒注册 + 推广 + 维护 / Outlook）

### 4.1 指纹需求

- 社媒/Outlook 注册风控核心看三件事：**IP 信誉**（代理质量）、**浏览器指纹一致性**（UA/时区/语言/屏幕/GPU 互洽）、**行为拟人度**（鼠标/键盘/节奏）。
- **Camoufox + BrowserForge** 恰好覆盖前两项，且档案种子持久化后「养了一个月的号，指纹始终如一」。
- **行为拟人度**：Camoufox 有鼠标轨迹；CloakBrowser 的 humanize 更强。v1 先用 Camoufox + 自研节奏控制（随机延迟、分步表单），v1.1 视预算引入 CloakBrowser。

### 4.2 多开与隔离

- 每个档案 = 独立进程 + 独立 user-data 目录 + 独立 Cookie 存储 + 独立代理。Camoufox 以 Playwright persistent context 即可实现，零额外成本。
- 建议并发：住宅代理成本敏感，单机 5~10 并发起步。

### 4.3 代理

- 三家引擎都支持 HTTP/SOCKS5 代理参数。FableTech 需要**代理池管理层**：批量导入、连通性测试、出口地理识别（ip-api）、与档案绑定时自动同步时区/locale（Camoufox 的 geoip 联动）。

### 4.4 自动化

- 注册流程（Outlook 为例）天然是**半自动**：表单可自动填，CAPTCHA（FunCaptcha）与短信验证必须人工介入 → FableTech 自动化框架必须是「步骤机 + 人工介入点」设计，而非全自动黑盒。
- 推广/维护（发帖、点赞、养号浏览）可全自动 + 调度（随机时段、随机间隔、失败重试）。

### 4.5 数据安全

- 账号密码、Cookie、代理凭证必须**本地 AES-256-GCM 加密**，主密码派生密钥，绝不落明文、绝不外传（商业产品的云同步是隐私与封号双风险，FableTech 坚持纯本地）。

## 5. 选型决策（最终）

| 组件 | 决策 | 关键理由 |
|---|---|---|
| 主指纹引擎 | **Camoufox** | 免费、源码级、MPL-2.0、活跃、200MB 轻量 |
| 增强引擎（可选） | **CloakBrowser**（license key，运行时按需下载） | 检测之王；自用合规；不进默认包 |
| Chromium 备选引擎 | **Patchright + 系统 Chrome** | 覆盖 Chromium-only 站点；Apache-2.0 |
| 指纹生成 | **BrowserForge**（种子持久化） | 统计真实 + 内部一致 |
| 自动化框架 | **自研 Recipe 步骤机**（半自动介入点 + 调度器） | 注册流程必须有 CAPTCHA/SMS 人工节点 |
| 产品外壳 | **Python + CustomTkinter GUI + SQLite** | 打包便携、无外部服务依赖、团队自维护 |
| 数据加密 | **AES-256-GCM + 主密码（scrypt 派生）** | 凭证/Cookie/代理口令本地加密 |

> **核心工程判断**：不自研浏览器内核（不可能也不必要）。FableTech = **产品外壳（我们 100% 自研）+ 引擎层（可插拔，主引擎免费开源）**。这既满足"属于 FableTech 自己的指纹浏览器"，又站在开源巨人的肩膀上。
