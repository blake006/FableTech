## 1. 快速开始

### 1.1 便携版安装（推荐）

1. 获取 `FableTech-1.0.0-win-x64-portable.zip`
2. 解压到**非系统盘**目录（如 `D:\FableTech\`），路径**不要含中文和空格**（如 `D:\FableTech\` 优于 `D:\我的工具\`）
3. 双击 **`FableTech.exe`** 启动

> 便携版所有数据都在解压目录的 `data/` 文件夹里：备份 = 复制整个文件夹，卸载 = 删除整个文件夹。

### 1.2 首次启动必做三件事

```
① 设置主密码（≥8 位，建议 12 位以上含大小写+数字）
② 设置页 → 引擎运行时 → 「一键安装运行时」（安装 camoufox 引擎，约 2-5 分钟）
③ 首次启动档案时按提示下载浏览器内核（约 1.3GB，一次性，耐心等待）
```

> ⚠️ **主密码遗忘 = 数据永久不可恢复**（设计如此）。请立即用密码管理器保存，并告知团队负责人。

### 1.3 开发模式（技术人员）

```bash
pip install -r requirements.txt -r requirements-runtime.txt
python -m fabletech            # GUI
python -m fabletech --help     # CLI
```

## 4. 代理池管理

### 4.1 批量导入代理

在「代理池」页粘贴代理列表（每行一条，支持三种格式混排）：

```
http://user:pass@1.2.3.4:8080
socks5://user:pass@5.6.7.8:1080
https://9.9.9.9:3128
```

- 用户名/密码自动加密存储，界面与日志中一律显示为 `socks5://u***:p***@host:port`
- 支持打标签分组（如 `us-residential`、`mobile-de`），方便按地区筛选

### 4.2 连通性测试与地理识别

- 点击「测试全部」或单条「测试」：验证 SOCKS/HTTP 握手 + 目标站点可达性 + 出口 IP 的国家/城市
- **注册类操作必须用住宅/移动代理**：数据中心（IDC）IP 会被 Outlook/社媒风控秒拒
- 测试结果中的国家/城市会在绑定时**自动同步档案的时区与语言**（Camoufox `geoip` 机制）

### 4.4 Hysteria2 / AnyTLS 代理（hy2:// / anytls://）

浏览器内核不能直连 Hysteria2（QUIC）与 AnyTLS（TLS 混淆）协议，FableTech 内置 **mihomo 本地中转**自动处理：首次使用自动下载中转内核（约 21MB，一次性），把上游协议转换成本地 SOCKS5 给浏览器使用，全程无感。

**导入方式**：代理池 → 批量导入，每行一条完整 URI：

```
hy2://密码@服务器:端口/?sni=域名&insecure=1&obfs=salamander&obfs-password=混淆密码
hysteria2://密码@服务器:端口/?sni=域名&insecure=1
anytls://密码@服务器:端口/?sni=域名&insecure=1
```

- `sni`：TLS SNI（缺省同主机名）；`insecure=1`：跳过证书校验
- `obfs=salamander&obfs-password=xxx`：Hysteria2 混淆参数（服务端开启时才需要）
- 参数会自动加密存储，档案绑定时自动生效

**测试**：选中代理点「连通测试」——中转型代理会**经中转实测完整链路**（启动本地中转 → 经其访问出口查询 → 自动回填出口国家/城市），比 TCP 探测更可靠。

**注意**：
- 「地理查询」按钮对中转型代理显示的是**服务器地理**（非出口）；出口地理请用「连通测试」
- 同一代理被多个档案绑定时共享一个中转进程，全部关闭后自动回收
- 中转内核与配置缓存在 `data/bin/` 与 `data/relays/`，换机器需重新下载

> 无参数简写也支持：`hy2://密码@host:port`（无 sni/insecure/obfs）。

### 4.5 代理使用规范

| 场景 | 建议 |
|---|---|
| Outlook 注册 | 住宅 IP，一档案一 IP，注册后 IP 至少稳定 7 天 |
| 社媒注册 | 住宅/移动 IP，同 IP 段账号密度 ≤ 3 |
| 日常维护（养号） | 可轮换，但同一天内不要跨国跳 |
| 发帖推广 | 尽量沿用注册 IP（稳定性 > 新鲜度） |

## 5. 档案管理

### 5.1 创建档案

「档案管理」→「新建档案」，填写：

| 字段 | 说明 |
|---|---|
| 名称 | 建议格式：`平台-序号-备注`，如 `outlook-07-us` |
| 平台标签 | outlook / x / tiktok / instagram / facebook … |
| 引擎 | **camoufox**（默认，推荐）｜ cloak（需订阅 key）｜ chromium（仅 Chromium-only 站点） |
| 代理 | 从代理池选择一条（可选，建议必选） |
| 分组 | 自定义分组，如 `7月批次` |
| 备注 | 自由文本 |

创建后系统自动生成**指纹种子**（seed）——同一档案每次启动的浏览器指纹（UA/屏幕/GPU/字体/时区…）**完全一致**，这是防关联的核心。

### 5.2 启动档案

- 双击档案或点「启动」→ 弹出原生浏览器窗口，即可**像普通浏览器一样手动操作**
- 窗口内的一切（Cookie、登录态、历史）自动持久化到该档案，**关闭后下次启动原样恢复**
- 「运行中」状态栏可查看当前启动的档案；重复启动同一档案会被阻止（防止指纹串号）

### 5.3 档案状态

| 状态 | 含义 | 处理 |
|---|---|---|
| 活跃 | 正常 | — |
| 异常 | 巡检发现登录失效/风控提示 | 人工复核，必要时重新验证 |
| 封禁 | 平台明确封禁 | 标记归档，分析原因（IP/指纹/行为） |

## 6. 实操一：Outlook 邮箱注册

**设计原理**：Outlook 注册的 CAPTCHA（FunCaptcha）与短信验证无法全自动绕过，FableTech 采用**半自动**——表单自动填写 + 人工介入点 + 完成后自动加密存档。

### 6.1 前置准备

1. 代理池导入一条**干净的住宅代理**并测试通过
2. 新建档案：名称 `outlook-XX`，引擎 camoufox，绑定该代理
3. 准备注册信息（姓名、生日、备用手机号）

### 6.2 执行步骤

**步骤 1：创建任务**
「任务调度」→「新建任务」：
- 配方：`outlook_register`
- 档案：选择刚建的档案
- 参数（JSON）：
```json
{
  "first_name": "Alex",
  "last_name": "Chen",
  "birth_year": "1995",
  "birth_month": "5",
  "birth_day": "15",
  "password": "YourStr0ng!Pass"
}
```
> `username` 可不填（系统自动生成）；`password` 必填，将加密存档

**步骤 2：自动执行（无需干预）**
浏览器自动打开 `signup.live.com` 并填写：姓名 → 生日 → 用户名 → 密码。拟人化输入节奏（随机击键延迟）。

**步骤 3：人工介入点 ① —— 人机验证**
- 任务状态变为**「等待人工」**（任务页高亮 + 弹窗提示）
- 在浏览器窗口中**手动完成 FunCaptcha**
- 回到 FableTech 点「继续」

**步骤 4：人工介入点 ② —— 短信验证**
- 同上，输入手机收到的验证码
- 点「继续」

**步骤 5：自动收尾**
- 系统检测注册完成 → **Cookie 加密存档** → 账号信息（用户名/密码/时间）写入档案元数据（加密）
- 任务标记「完成」，日志+截图归档

### 6.3 注册后养号建议

| 时间 | 动作 |
|---|---|
| 当天 | 不要发信，登录后浏览 5-10 分钟，完善资料 |
| 第 2-3 天 | 每天登录 1 次，发 1-2 封正常邮件（给熟人地址） |
| 第 4-7 天 | 正常使用，绑定手机/恢复邮箱 |
| 之后 | 用「健康巡检」任务每周自动检查登录态 |

## 7. 实操二：社媒发帖（X / TikTok）

### 7.1 X（Twitter）发帖

前置：档案已登录 X（首次手动登录，Cookie 自动持久化）

「任务调度」→「新建任务」：
- 配方：`x_post`
- 档案：已登录的 X 档案
- 参数：
```json
{ "text": "Hello from FableTech! #automation" }
```

执行流程：启动档案 → 校验登录态 → 打开发帖框 → 拟人输入文本 → 发布 → 校验结果 → 记录日志。

### 7.2 TikTok 发视频

- 配方：`tiktok_post`
- 参数中包含视频文件路径与文案
- 若站点改版导致选择器失效，按《维护手册》第 5 节更新 `SELECTORS` 常量

### 7.3 发帖纪律（防封）

- 新号前 7 天：每天 ≤ 2 帖，间隔 ≥ 2 小时
- 同 IP 账号数 ≤ 3
- 内容去重：不要多账号发完全相同文案
- 发现异常（验证码频繁/功能受限）：立即停该档案 3-7 天

## 8. 任务调度

| 功能 | 用法 |
|---|---|
| 立即执行 | 新建任务时调度方式选「立即」 |
| 定时执行 | 选「定时」，填 cron 式时间（如每天 09:30） |
| 间隔执行 | 选「间隔」，填分钟数 |
| 并发上限 | 默认 2，避免同时启动过多档案拖垮机器 |
| 失败重试 | 自动重试最多 3 次（指数退避），每次失败自动截图 |
| 等待人工 | 任务变黄「等待人工」→ 完成人工操作 → 点「继续」 |
| 停止/删除 | 任务页操作；运行中任务会安全关闭对应档案 |

> 建议：批量注册时用「间隔执行」（如每 30 分钟一个），模拟真人注册节奏，不要并发猛冲。

## 9. Cookie 导入导出

### 9.1 导出（团队交接/备份）

```bash
fabletech-cli.exe --password <主密码> export-cookies <档案ID> cookies.json
```

导出格式：JSON（含域名/名称/值/过期等完整字段），文件本身**未加密**——请存入团队安全位置后删除工作副本。

### 9.2 导入（复用既有登录态）

```bash
fabletech-cli.exe --password <主密码> import-cookies <档案ID> cookies.json
```

支持 **Netscape 格式**（`cookies.txt`，从浏览器扩展导出）与 JSON 两种格式。导入后该档案即具备对应账号的登录态，无需重新登录。

> ⚠️ Cookie 即账号凭证。导出文件等同账号权限，传递必须走团队加密渠道（如加密压缩包 + 单独传密码）。

## 10. 账号健康巡检

- 配方：`health_check`，建议对全部活跃档案设置**每周一次**的定时巡检
- 巡检内容：启动档案 → 打开平台首页 → 判定登录态/风控提示 → 更新档案状态（活跃/异常/封禁）
- 异常档案在「档案管理」页标红，需人工复核

## 11. 日志审计

- 「日志审计」页查看全部日志：操作记录、任务执行、引擎事件
- **自动脱敏**：代理 URL 显示为 `socks5://u***:p***@host:port`；密码类字段永不入日志
- 失败任务自动截图存于 `data/screenshots/`
- 建议每周导出一次日志存档（团队审计用）

## 12. 命令行（CLI）用法

适用于脚本化批处理与无人值守场景。在便携版目录：

```bash
# 查看帮助
fabletech-cli.exe --help

# 主密码可用环境变量传入（避免命令行历史泄露）
export FABLETECH_MASTER_PASSWORD=<主密码>

# 档案管理
fabletech-cli.exe create-profile --name outlook-08 --platform outlook --proxy-id <代理ID>
fabletech-cli.exe launch <档案ID>
fabletech-cli.exe engines                    # 引擎状态检测

# 自动化
fabletech-cli.exe run-recipe --profile <档案ID> --recipe outlook_register --params params.json
fabletech-cli.exe run-recipe --profile <档案ID> --recipe x_post --params '{"text":"hi"}'

# Cookie
fabletech-cli.exe export-cookies <档案ID> out.json
fabletech-cli.exe import-cookies <档案ID> in.json

# 代理
fabletech-cli.exe proxy-test <代理ID>
```

## 13. 安全规范与合规红线

### 团队安全规范

1. 主密码仅负责人保管，成员离职立即更换
2. 导出的 Cookie 文件等同账号凭证，按机密文件管理
3. `data/` 目录按机密对待：不进网盘公开分享、不进 git
4. 定期备份 `data/` 到加密存储（见《维护手册》第 2 节）

### 合规红线（不可触碰）

- ❌ 欺诈、垃圾信息、黄赌毒内容
- ❌ 规避金融/政府/司法类风控
- ❌ 爬取受保护数据、攻击行为
- ❌ 买卖非本人实名的账号用于违法用途
- ✅ 仅用于管理**团队自有账号**的正当营销运营，遵守各平台服务条款与当地法律

## 14. 常见问题 FAQ

**Q1：启动档案提示「camoufox 浏览器未下载」？**
首次启动需下载约 1.3GB 浏览器内核（一次性）。在设置页点「一键安装运行时」自动完成；或命令行 `python -m camoufox fetch`。下载慢是正常的（受网络影响），耐心等待。

**Q2：任务卡在「等待人工」？**
设计如此——CAPTCHA/短信验证需要人工。完成浏览器中的验证后，回任务页点「继续」。

**Q3：指纹会变吗？**
不会。同一档案的指纹由种子（seed）确定性生成，跨会话恒定——这是防关联的关键。如需"换指纹"，请新建档案。

**Q4：能同时开多少个档案？**
默认并发 2（可在任务页调整）。建议同时运行 ≤ 5 个，太多会拖慢机器并增加行为关联风险。

**Q5：Chromium 引擎和 Camoufox 有什么区别？**
Camoufox（主引擎）做完整指纹伪装；Chromium 引擎只修自动化痕迹、**不伪造指纹**，仅用于必须 Chromium 的少数站点，多账号场景不要用。

**Q6：换电脑了怎么办？**
复制整个便携目录（含 `data/`）到新电脑即可，主密码不变则数据直接可用。注意引擎运行时需在新机器重新安装。

**Q7：Outlook 注册到某一步报错？**
多为选择器随站点改版失效或网络超时。任务自动重试 3 次；仍失败则看日志+截图，人工接管完成剩余步骤，Cookie 照常存档。
