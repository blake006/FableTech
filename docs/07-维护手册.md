## 1. 系统架构速览

```
FableTech（Python 3.11+）
├── GUI（CustomTkinter）—— 五页面：档案/代理/任务/日志/设置
├── CLI（fabletech-cli）—— 7 子命令，脚本化入口
├── 服务层：ProfileService / ProxyService / CookieVault / Scheduler
├── 引擎层（可插拔）
│   ├── camoufox（主，Firefox 定制，MPL-2.0）
│   ├── cloak（可选，CloakBrowser，license key）
│   └── chromium（备选，patchright + 系统 Chrome）
├── 存储：data/fabletech.db（SQLite）+ data/cookies/*.enc（AES-256-GCM）
└── 安全：主密码 → scrypt → 内存密钥（永不落盘）
```

**关键文件**：

| 路径 | 内容 |
|---|---|
| `data/fabletech.db` | SQLite 主库（档案/代理/任务/日志/设置） |
| `data/cookies/<档案ID>.enc` | 加密 Cookie 存档 |
| `data/screenshots/` | 任务失败截图 |
| `data/logs/` | 文件日志（如有） |
| `portable.flag` | 便携模式标记（存在则数据落 `./data/`） |

## 2. 数据备份与恢复

### 2.1 备份策略

| 频率 | 内容 | 方式 |
|---|---|---|
| 每日 | `data/` 增量 | 拷贝 `fabletech.db` + 当日新增 `.enc` |
| 每周 | `data/` 全量 | 压缩 `data/` → 加密网盘/内网 NAS |
| 重大操作前 | `data/` 快照 | 复制整个 `data/` 到 `data-backup-<日期>/` |

> `data/` 内含加密数据，但**备份文件本身应按机密管理**（加密存储 + 访问控制）。

### 2.2 恢复

1. 停止 FableTech（关闭所有窗口）
2. 用备份的 `data/` 覆盖当前 `data/`
3. 重新启动，输入原主密码验证

### 2.3 迁移到新机器

```bash
# 1. 旧机器：停应用 → 打包整个便携目录（含 data/）
# 2. 新机器：解压 → 双击 FableTech.exe
# 3. 新机器需重新安装引擎运行时（设置页一键安装）并下载浏览器内核
# 4. 主密码不变 → 数据直接可用
```

## 3. 引擎运行时管理

### 3.1 引擎依赖清单

| 引擎 | Python 包 | 浏览器二进制 |
|---|---|---|
| camoufox | `camoufox` + `playwright` | camoufox 定制 Firefox（~1.3GB，首次自动下载） |
| chromium | `patchright` + `playwright` | 系统 Chrome（优先）或 patchright 自带 Chromium |
| cloak | `cloakbrowser`（需订阅） | CloakBrowser Chromium（按 license 下载） |

### 3.2 安装 / 重装

```bash
# GUI：设置 → 引擎运行时 → 一键安装运行时

# 或手动（便携版解压目录内的 python 环境）：
pip install -r engines-runtime/requirements-runtime.txt
python -m camoufox fetch        # 下载 camoufox 内核
```

### 3.3 版本升级

```bash
pip install -U camoufox playwright patchright
python -m camoufox fetch        # 内核与包版本需匹配，fetch 会拉取配套版本
```

> camoufox 包升级后**必须重新 fetch**——包与浏览器版本严格配对，否则引擎报 "not installed"。

### 3.4 mihomo 中转内核（Hysteria2/AnyTLS 专用）

| 项 | 说明 |
|---|---|
| 用途 | 把 hy2://anytls:// 上游转本地 SOCKS5（浏览器内核只认 HTTP/SOCKS5） |
| 二进制 | `data/bin/mihomo.exe`（约 21MB，v1.19.32，首次使用中转型代理时自动下载） |
| 运行实例 | 每个代理一个本地 mixed 端口（127.0.0.1 随机端口），按 proxy_id 引用计数复用 |
| 配置/日志 | `data/relays/<proxy_id>.yaml` / `.log` |
| 卡死排查 | 查看 `data/relays/<proxy_id>.log`；内核损坏可删 `data/bin/mihomo.exe` 触发重新下载 |
| 许可 | mihomo 为 GPL-3.0，运行时按需下载不预装不分发（与 camoufox 同策略） |

## 4. camoufox 浏览器内核更新

- camoufox 跟随 Firefox 上游版本，**内核更新 = 反检测能力更新**，建议每月检查一次
- 检查方式：`fabletech-cli.exe engines` 查看当前版本；PyPI 查看 camoufox 最新版
- 更新流程见 3.3；更新后跑一次冒烟：
```bash
fabletech-cli.exe --password <主密码> create-profile --name 升级验证
fabletech-cli.exe --password <主密码> launch <新档案ID>   # 能开出窗口即正常
```

## 5. 配方（Recipe）维护与站点改版适配

### 5.1 配方文件位置

```
fabletech/core/automations/
├── outlook_register.py   # Outlook 注册（半自动）
├── x_post.py             # X 发帖
├── tiktok_post.py        # TikTok 发视频
└── health_check.py       # 账号巡检
```

### 5.2 站点改版处理流程

1. 任务失败 → 看 `data/screenshots/` 截图 + 日志
2. 定位失效选择器：各配方文件顶部的 `SEL` / `SELECTORS` 常量
3. 用浏览器 DevTools 抓新选择器，更新常量
4. 重跑任务验证

**示例（X 发帖框选择器失效）**：
```python
# fabletech/core/automations/x_post.py
SEL = {
    "compose": '[data-testid="tweetTextarea_0"]',  # ← 更新这里
    "post_btn": '[data-testid="tweetButtonInline"]',
}
```

### 5.3 新增配方

继承 `automations/base.py` 的 `Recipe` 基类：

```python
class MyRecipe(Recipe):
    name = "my_recipe"
    title = "我的配方"
    def steps(self, ctx):
        return [
            Step("步骤一", self._do),
            Step("人工介入", None, requires_human=True, human_prompt="请手动完成X后点继续"),
        ]
```

在 `automations/__init__.py` 的 `RECIPES` 注册表中登记即可被 CLI/GUI 识别。

## 6. 故障排查手册

### 6.1 引擎不可用

| 现象 | 原因 | 处理 |
|---|---|---|
| 「未安装 camoufox」 | 包缺失 | 设置页一键安装 / `pip install camoufox` |
| 「浏览器未下载」 | 内核未 fetch | `python -m camoufox fetch`（1.3GB，耐心等） |
| 「not installed: official X, ...」 | 包与内核版本不配对 | 升级包后重新 fetch |
| camoufox 升级后全挂 | 同上 | 回退包版本或重新 fetch |

### 6.2 档案启动失败

| 现象 | 原因 | 处理 |
|---|---|---|
| 窗口闪退 | 代理不通/内核损坏 | 先 `proxy-test`；重新 fetch 内核 |
| 超时无窗口 | 内核首次下载中 | 等下载完成；看设置页引擎状态 |
| 「档案运行中」重复启动被拒 | 进程未清理 | 任务页/档案页「强制关闭」，或重启应用 |
| 白屏/花屏 | GPU 渲染问题 | 在 camoufox 启动参数加 `--disable-gpu`（需改引擎代码） |

### 6.3 代理问题

| 现象 | 处理 |
|---|---|
| 测试超时 | 代理本身不通；换线路重试 |
| 测试通过但注册被拒 | IP 是机房段（IDC）——换住宅代理 |
| 时区与 IP 不符 | 确认档案绑定代理时用了「自动同步地理」；chromium 引擎无此能力 |

### 6.4 GUI 异常

| 现象 | 处理 |
|---|---|
| 双击无反应 | 任务管理器查 `FableTech.exe`；看 `data/` 是否有 db 锁（另一实例在跑） |
| 界面乱码 | Windows 控制台执行 `chcp 65001` 后重启 |
| 主密码输入框不接受 | 检查是否 ≥8 位 |

### 6.5 数据异常

| 现象 | 处理 |
|---|---|
| 「主密码错误」但确定没错 | 键盘布局/大小写；确认没粘贴多余空格 |
| db 损坏（SQLITE_CORRUPT） | 从备份恢复 `fabletech.db` |
| Cookie 解密失败 | 该档案是用旧主密码加密的——主密码更换后需重新导入 Cookie |

## 7. 日志解读

日志位置：GUI「日志审计」页 + `data/`（如有文件日志）。

| 级别 | 含义 | 关注度 |
|---|---|---|
| INFO | 正常流程（档案启动、任务完成） | 低 |
| WARNING | 可恢复问题（存档失败、未检测到完成页） | 中——出现频繁要查 |
| ERROR | 任务失败、引擎异常 | 高——必看截图 |

脱敏规则：代理显示 `socks5://u***:p***@host:port`；密码永不入日志。若在日志中看到明文凭证，属 bug，请报告。

## 8. 主密码管理

| 场景 | 操作 |
|---|---|
| 定期更换 | 无在线换密功能（v1）。流程：导出全部档案包 → 删除 `data/` → 重新初始化 → 导入 |
| 成员离职 | 同上 + 更换后通知全员新密码 |
| 遗忘 | **不可恢复**。删 `data/` 重来（档案全丢，务必先备份） |

> v1.1 规划：主密码在线更换（重加密全部数据）。

## 9. 性能与并发调优

| 项 | 默认 | 建议 |
|---|---|---|
| 调度并发 | 2 | 8GB 内存 ≤3；16GB ≤5；32GB ≤8 |
| 单档案内存 | ~600MB-1GB | 同时运行 N 个档案 ≈ N × 800MB |
| 磁盘 | — | 每个档案 user_data 约 100-500MB，定期清理废弃档案 |
| 网络 | — | 批量注册用「间隔执行」而非并发，降低关联风险 |

磁盘清理：
```bash
# 删除已归档档案的数据（GUI 删除档案会自动清 user_data）
# 手动清理截图（保留最近 30 天）
find data/screenshots -name "*.png" -mtime +30 -delete
```

## 10. 版本升级流程

1. **看 release note**：GitHub `blake006/FableTech` Releases
2. **备份**：`data/` 全量快照（升级前必做）
3. **升级便携包**：下载新 zip → 停旧实例 → 用新 zip 覆盖（`data/` 保留不动）
4. **升级运行时**：设置页一键安装（或 `pip install -U -r requirements-runtime.txt` + `camoufox fetch`）
5. **冒烟验证**：`engines` 状态全绿 + 启动一个测试档案
6. **回滚预案**：出问题则恢复旧版目录 + `data/` 备份

## 11. 卸载与迁移

- **便携版卸载**：删除整个解压目录（数据随之删除——先备份）
- **迁移**：见 2.3，复制目录即迁移
- **引擎缓存**（ camoufox 内核，~1.3GB）：位于 `%LOCALAPPDATA%\camoufox\`，卸载 FableTech 后如不再使用可手动删除以释放空间
